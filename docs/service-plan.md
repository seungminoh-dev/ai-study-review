# 모아이 서비스 기획서 v0.4

> AI와 공부한 대화를 **복습 카드와 지식 지도**로 바꿔서, 지하철이나 침대에서 2~3분씩 되새기게 하는 서비스.

- 작성일: 2026-10-17 (v0.4: 이름을 모아이로 정함, MVP 0 코드 완료. v0.3: TypeScript·Cloudflare Worker로 결정, 기술 내용은 설계서로 옮김)
- 대상: 나 + 친구 10명 클로즈드 베타. 전원 Claude Pro($20) 또는 Max($100) 요금제
- 가입: 초대받은 사람만
- 제약: Claude API 월 $100 이하(내 Console API 키, 서버에서만 호출), 인프라 사실상 $0, 웹(모바일 우선)
- 관련 문서: [설계서](design.md) (구현 설계, MVP별 계획), [MVP 0 실행 가이드](mvp0-runbook.md), [ADR 0001](adr/0001-runtime.md) (런타임 결정), [이름 후보](names.md)

## 1. 문제 정의

| # | 페인포인트 | 지금 모습 |
|---|---|---|
| P1 | **휘발** | AI한테 답을 들은 순간 이해한 기분이 들지만, 따로 정리하지 않으면 남지 않는다. 정리는 귀찮아서 안 한다. |
| P2 | **복습 부재** | 언제 무엇을 다시 봐야 하는지 아무도 관리하지 않는다. 망각 곡선대로 잊는다. |
| P3 | **연결 손실** | `불변 객체 → final → 방어적 복사 → 깊은/얕은 복사`처럼 꼬리질문으로 넓어진 지식이 대화 스레드 안에 묻힌다. |
| P4 | **학습 맥락** | 공부하는 시간이 이동 중이거나 누워 있을 때다. 폰, 한 손, 2~3분, 자주 끊긴다. |
| P5 | **면접 특수성** | 목표는 "알아보기"가 아니라 "내 말로 설명하기"다. 객관식만 풀면 아는 것 같은 착각이 생긴다. |

## 2. 핵심 인사이트 4가지

1. **재료는 대화 로그가 아니라 코칭의 판정 결과다.**
   지금 쓰는 코치 지침이 이미 `[맞음]/[애매]/[틀림]/[빠짐]` 판정, 막힌 지점, 핵심 용어, 다음에 볼 질문, 확정된 최종 버전을 만들어 낸다. 이걸 구조화해서 저장하기만 하면 된다.
2. **내가 했던 오답이 가장 좋은 오답 보기다.**
   "깊은 복사는 외부에서 받아올 때 새 객체로 복사하는 것"처럼 내가 실제로 했던 틀린 설명을 객관식 보기로 다시 보여 준다. 시중 문제집은 이걸 못 준다.
3. **카드는 대화 중인 Claude가 만든다.**
   맥락을 가장 많이 아는 시점은 대화 도중이다. 끝난 뒤 로그를 파싱하면 품질도 떨어지고 API 비용도 든다. 대화 중에 만들면 사용자의 Claude 구독으로 처리되니 **서버 API 비용이 0**이다.
4. **복습 스케줄링은 AI가 아니라 알고리즘이 한다.**
   간격 반복은 FSRS(Anki에 들어 있는 오픈소스 알고리즘)가 결정적으로, 무료로, 검증된 방식으로 처리한다. AI는 "무엇을, 어떤 형태로 물을지"와 "설명 채점"에만 쓴다.

## 3. 사용 시나리오 (하루)

1. **21:30 침대** — claude.ai 프로젝트 "면접 코치"에서 불변 객체를 코칭받는다. "정리해줘"라고 하면 Claude가 3줄 정리를 하고 `save_learning` 도구를 호출한다.
   → "개념 5개, 카드 7장, 다음에 볼 질문 2개를 저장했어요."
2. **다음 날 08:10 지하철** — 푸시 알림: "오늘 복습 8장 · 약 3분". OX → 객관식 → 빈칸 순서로 푼다. 깊은 복사 객관식에서 또 예전 내 오답을 고른다. 해설과 함께 "이 개념은 아직 흔들려요. Claude에서 이어서 공부하기" 버튼이 뜬다.
3. **버튼 탭** — 이어서 공부할 프롬프트가 복사된다. 프로젝트에 붙여 넣으면 Claude가 `get_learner_context`로 내 기록을 읽고 "지난번엔 깊은 복사를 받아오는 시점으로 설명했죠"라며 시작한다.
4. **며칠 뒤** — 아래 단계 카드가 익숙해지면 불변 객체가 "설명하기" 카드로 승급한다. 30초 설명을 쓰고, 내가 확정했던 최종 버전과 핵심 요소 체크리스트로 자가 채점한다.
5. **주말** — 친구 리그에서 이번 주 XP 순위를 본다.

## 5. 지식을 어떻게 빼오나

### 5.1 선택지 비교

| 방식 | 공부하는 곳 | 추출 비용 | 친구 온보딩 | 판정 |
|---|---|---|---|---|
| **A. Remote MCP 커넥터** (claude.ai 프로젝트에 우리 서버를 커넥터로 추가) | 지금처럼 폰 claude.ai 앱 | 0 (사용자 구독) | 커넥터 URL 1개 추가 | **주력** |
| B. Claude Code 플러그인 (skill + hook, MCP는 claude.ai 커넥터를 그대로 씀) | 터미널 (클라우드 세션은 플러그인을 불러오지 않는다) | 0 (사용자 구독) | 플러그인 설치 | 보조 (MVP 3) |
| C. 웹에 대화 붙여넣기 → 서버가 추출 | 어디든 | API 사용 (건당 $0.003~0.12, 모델에 따라) | 없음 | 폴백 (MVP 2) |
| D. claude.ai 데이터 내보내기(zip) 일괄 가져오기 | 과거 대화 | API 사용 (Batch로 50% 할인) | 수동 | 초기 이관용 (MVP 3) |

### 5.2 왜 "로컬 Claude Code에서 다 만들고 웹은 DB+UI만"이 아니라 A인가

방향은 맞다. **LLM 일은 사용자 쪽 Claude가 하고, 서버는 저장·스케줄·UI만 한다**는 원칙은 그대로 가져간다. 다만 그 "사용자 쪽"을 로컬 CLI가 아니라 **실제로 공부하는 곳**으로 옮긴다.

- 공부는 폰의 claude.ai 프로젝트에서 일어난다. Claude Code hook은 claude.ai 채팅 내용을 볼 수 없다. CLI만 쓰면 누워서 하던 공부를 책상으로 옮겨야 해서 P4와 충돌한다.
- 사후 파싱보다 대화 중 추출이 정확하다. Claude는 자기가 내린 판정과 사용자가 막힌 지점을 이미 알고 있다.
- 친구 온보딩이 쉽다. CLI 설치 대신 URL 하나만 추가하면 된다.
- 참고: Claude Code는 데스크톱 전용이 아니다. Claude 앱과 웹에서 클라우드 세션으로도 돌고, 레포의 `.claude/`에 커밋한 hook과 skill도 거기서 실행된다 (플러그인은 불러오지 않는다). 다만 코딩용 환경이라 코칭 대화에는 claude.ai 채팅이 더 자연스럽다. 그래서 B는 "터미널에서 기술 공부할 때"용 보조 경로로 둔다.

### 5.3 시스템 구성 (요약)

Cloudflare Worker 하나(TypeScript, Free 플랜)에 MCP 서버, REST API, PWA 정적 파일, 매분 Cron이 모두 들어간다. 데이터는 D1(SQLite)에 둔다. 자세한 구성, 데이터 모델, API, MVP별 계획은 [설계서](design.md)에 있다.

claude.ai 커넥터가 서버에 요구하는 것:

- 공개 HTTPS 주소와 IPv4 A 레코드. 호출은 폰 앱에서 쓸 때도 항상 Anthropic 클라우드(`160.79.104.0/21`)에서 온다.
- 다른 호스트로 리다이렉트하지 않는다 (인증 헤더가 사라진다).
- 도구 호출은 240초 안에 응답한다.
- 친구들은 커넥터를 웹에서 한 번 추가하고, 도구를 "항상 허용"으로 바꿔 둔다. 그래야 폰에서 승인 버튼을 누르지 않아도 된다.

### 5.4 MCP 도구

| 도구 | 언제 | 하는 일 |
|---|---|---|
| `find_concepts` | 저장 직전 | 비슷한 기존 개념을 돌려준다. Claude가 같은 개념이면 기존 `key`를 재사용한다. 임베딩 없이 중복을 막는다. |
| `save_learning` | "정리" 요청 시 | 판정·오답·개념·연결·카드·다음 질문을 저장하고, 저장 요약과 웹 링크를 돌려준다. |
| `get_learner_context` | 코칭 시작 시 | 이 주제의 과거 오답, 확정 최종 버전, 연결 개념, 약한 카드를 돌려준다. 코칭이 개인화된다. |
| `get_review_queue` / `submit_review` (MVP 3) | 채팅으로 복습할 때 | "오늘 복습 퀴즈 내줘"를 채팅 안에서 처리한다. |

**카드 생성 규칙은 프로젝트 지침이 아니라 `save_learning`의 도구 설명과 스키마에 둔다.** 서버에서 규칙을 고치면 친구 10명의 세션에 바로 반영되고, 각자 지침을 고칠 필요가 없다. 도구 설명문 초안은 설계서 부록 A에 있다.

### 5.5 프로젝트 지침에 추가할 부분

기존 코치 지침의 `# 세션 정리` 섹션을 설계서 부록 B의 "모아이 연동" 블록으로 바꾼다. 앱 설정 화면에서 복사할 수 있게 한다. 바뀌는 점은 세 가지다.

- 코칭을 시작할 때 `get_learner_context`로 과거 오답부터 확인한다.
- "정리해줘"를 들으면 3줄 정리와 함께 `find_concepts` → `save_learning`으로 저장한다.
- "이어서 공부하기"로 붙여 넣은 `[모아이:key]`를 알아본다.

면접 코치가 아닌 일반 Q&A 세션에서도 "이거 저장해줘"라고 하면 카드로 만든다. 판정 데이터가 없으면 오답 보기는 Claude가 만든다.

### 5.6 Claude Code 플러그인 (MVP 3)

```
moai-plugin/
├── .claude-plugin/plugin.json
├── skills/
│   ├── coach/SKILL.md        # 지금 쓰는 코치 지침 이식 (/coach)
│   └── capture/SKILL.md      # 현재 세션을 save_learning으로 저장 (/capture)
└── hooks/hooks.json          # Stop hook: 저장 안 한 학습이 있으면 저장하라고 알림
```

- Stop hook은 입력의 `last_assistant_message`(문서 권장, `transcript_path`는 늦게 갱신될 수 있음)를 보고, 코칭 흔적(`[틀림]` 등)은 있는데 저장한 적이 없으면 `{"decision": "block", "reason": "학습 내용을 /capture로 저장하라"}`를 돌려준다. `reason`은 사용자가 아니라 Claude에게 전달된다. 무한 반복을 막으려고 `stop_hook_active`가 true면 그냥 통과시킨다.
- 플러그인에는 MCP 서버를 넣지 않는다.
  - 친구가 Claude Code에 구독 계정으로 로그인하면 claude.ai에 추가한 커넥터가 자동으로 보인다.
  - 플러그인 `.mcp.json`에 같은 URL을 넣으면 그쪽이 우선해서 커넥터를 가린다.
  - 게다가 MCP 주소에 사용자별 비밀 토큰이 들어 있어서, 친구 모두가 받는 플러그인 하나에 고정 주소를 넣을 수도 없다.
- 친구 설치: `/plugin marketplace add seungminoh-dev/ai-study-review` → `/plugin install moai`.

## 6. 카드

### 6.1 카드 사다리

| 단계 | 카드 형태 | 측정하는 것 | 채점 |
|---|---|---|---|
| 1. 알아보기 | OX, 객관식 (내 오답이 보기로) | 구분할 수 있나 | 자동 |
| 2. 떠올리기 | 빈칸(보기를 누름), 코드 읽기 ("이 코드 컴파일되나요?") | 단서 보고 꺼낼 수 있나 | 자동 |
| 3. 설명하기 | 30초 설명 (텍스트, 나중에 음성) | 내 말로 설명할 수 있나 | 자가 채점 (기본) / AI 채점 (선택, 쿼터) |
| 보너스 | 꼬리질문 체인 (MVP 3) | 연결된 개념을 이어서 답할 수 있나 | 단계별 |

- 카드의 단계는 Claude가 정하지 않고 서버가 카드 종류로 정한다. 코드 없는 OX·객관식은 1단계, 빈칸과 코드가 있는 OX·객관식은 2단계, 설명하기는 3단계다.
- 개념 안에서 지금 열린 단계 카드의 FSRS 안정도(stability)가 모두 7일을 넘으면 그다음 단계 카드가 열린다. 설명하기 카드는 처음에 늘 잠겨 있다.
- 틀렸을 때 단계를 내리는 규칙은 넣지 않는다. FSRS가 간격을 줄이는 것으로 충분한지 MVP 2 데이터를 보고 정한다.
- 설명하기 카드의 자가 채점: 내가 확정한 최종 버전 + 핵심 요소 체크리스트 + 두괄식 여부를 보고 4단계(다시/어려움/좋음/쉬움)로 매긴다. 무료다.
- AI 채점: 코치 지침과 같은 `[맞음]/[애매]/[틀림]/[빠짐]` 기준으로 판정만 하고 정답은 말하지 않는다.

### 6.2 카드 생성 규칙 (도구 설명에 들어갈 내용)

- 카드 1장에는 사실 1개만 (최소 정보 원칙).
- 정답은 그 세션에서 확정된 내용(`[맞음]` 판정 또는 코치가 설명한 부분)에서만 가져온다. 세션에 없던 사실을 새로 지어내지 않는다.
- 객관식 보기: 정답 1개 + 내 오답(있으면 반드시) + 그럴듯한 오답. 3~4지선다.
- 해설은 1~2문장. 왜 틀렸는지를 쓴다.
- 개념당 카드 2~4장, 서로 다른 단계로.

### 6.3 `save_learning` 페이로드 예시 (불변 객체 세션)

전체 스키마는 설계서 §6.4에 있고, 같은 내용이 테스트 견본 `packages/shared/fixtures/immutable-object.json`에 있다 (빈칸 카드 1장이 더 있다). 카드에 단계(rung)는 넣지 않는다.

```json
{
  "topic": "불변 객체를 쓰는 이유와 만드는 방법",
  "source": "claude.ai",
  "final_answer": "(세션에서 확정한 사용자 문장 그대로)",
  "concepts": [
    { "key": "immutable-object", "name": "불변 객체" },
    { "key": "final-variable", "name": "변수에 붙인 final" },
    { "key": "defensive-copy", "name": "방어적 복사" },
    { "key": "deep-copy", "name": "깊은 복사" },
    { "key": "shallow-copy", "name": "얕은 복사" }
  ],
  "edges": [
    { "from": "immutable-object", "to": "final-variable", "type": "prerequisite" },
```

## 7. 데이터

데이터 모델(D1 스키마)은 설계서 §5에 있다. 제품 쪽 원칙만 적는다.

- 대화 원문은 오래 저장하지 않는다. 붙여넣기 원문은 추출이 끝날 때까지만 두고 바로 지운다. 그 밖에는 구조화된 결과만 저장한다 (친구 데이터 신뢰 문제).
- 각자 자기 데이터만 본다. 친구 리그에는 XP 합계만 보인다.
- 언제든 내 데이터를 내보내거나 계정을 지울 수 있다 (MVP 2).

## 8. 복습 스케줄링과 리마인드

자세한 규칙은 설계서 §9, §10에 있다.

- **알고리즘**: FSRS (`ts-fsrs`). 목표 기억률 90%, 최대 간격 180일.
- **자동 채점 → FSRS 등급**: 오답 = 다시(1), 정답이지만 15초 넘게 걸림 = 어려움(2), 정답 = 좋음(3). 쉬움(4)은 정답 뒤에 "너무 쉬웠어요"를 눌렀을 때만 준다. 찍어서 빨리 맞힌 카드의 간격이 지나치게 늘어나지 않게 하려는 것이다.
- **형제 카드 분산**: 같은 개념 카드는 하루에 1장만 낸다.
- **하루 상한**: 새 카드 10장, 복습 30장 (설정 가능). 밀렸을 때는 "가볍게 5장" 모드.
- **세션 길이**: 기본 8장, 약 3분. 지하철 한두 정거장.
- **하루의 경계**: 04:00 KST. 새벽에 한 복습은 전날로 센다.
- **리마인드**: 사용자가 정한 시간(예: 08:10, 22:30)에 웹 푸시. 매분 도는 Cron이 시각이 된 알림만 골라 보낸다. 30분 넘게 늦은 알림은 버린다. iOS는 16.4 이상에서 홈 화면에 추가한 PWA만 웹 푸시를 받는다. 온보딩에서 "홈 화면에 추가"를 안내한다.
- **오프라인**: 오늘 큐를 미리 받아 두고, 답은 기기에 쌓았다가 연결되면 보낸다.

## 9. 재미 요소 (MVP 2)

- 스트릭 + 일일 목표 (기본 5장, 작게 시작해서 끊기지 않게)
- 스트릭 프리즈 (주 1회)
- XP: 카드 정답, 설명하기 완료, 새 개념 캡처
- **친구 리그**: 10명 주간 XP 순위. 딱 리그 하나 크기.
- **오늘의 꼬리물기** (MVP 3): 연결된 개념 3개를 이어서 묻는 체인 (`불변 객체 → 방어적 복사 → 깊은 복사`). 면접관 꼬리질문 연습.
- 지식 지도에서 개념이 회색(아직 안 배움) → 노랑(흔들림) → 초록(익숙함)으로 바뀌는 걸 본다.

## 10. 비용

### 10.1 LLM 비용 (월 $100 한도)

주력 경로(A, B)는 **서버 API 비용 0**이다. API는 아래 두 곳에서만 쓴다 (MVP 2부터).

| 항목 | 가정 (1회) | Haiku 5.5 | Sonnet 5.5 | Opus 5.5 |
|---|---|---|---|---|
| 설명하기 AI 채점 | 입력 2K / 출력 0.4K 토큰 | $0.0004 | $0.008 | $0.016 |
| 월 3,000회 (10명 × 하루 10회) | | **$1.2** | **$24** | **$48** |
| 붙여넣기 추출 (폴백) | 입력 15K / 출력 3K 토큰 | $0.003 | $0.06 | $0.12 |
| 월 200건 (10명 × 주 5건) | | **$0.6** | **$12** | **$24** |
| **합계 (thinking 제외)** | | **~$2** | **~$36** | **~$72** |
| **합계 (thinking 포함 가정)** | 채점 +0.6K, 추출 +2K 출력 토큰 | **~$3** | **~$58** | **~$116 (초과)** |

- 단가 기준: Haiku 5.5 $0.10/$0.50, Sonnet 5.5 $2/$10, Opus 5.5 $4/$20 (입력/출력, 100만 토큰당, 2026-10 기준).
- 토큰 수는 가정이다. 위 표는 사용량을 넉넉하게 잡은 값이고, 실제 값은 관리자 사용량 화면에서 잰다.
- 세 모델 모두 기본으로 adaptive thinking이 켜져 있고, thinking 토큰은 출력 단가로 과금된다. 끄는 방법은 모델마다 다르다. Haiku 5.5는 effort가 high 이하일 때만 `disabled`로 끌 수 있다. Sonnet 5.5는 `disabled`가 400 에러이고, effort high 이하에서 `between_tools`로만 끌 수 있다. Opus 5.5는 끌 수 없고 effort만 낮출 수 있다.
- 기본 모델은 Opus 5.5(effort low)이고 설정값 하나로 바꿀 수 있다. 예산 가드가 사용자당 월 $6, 전체 월 $90에서 AI 채점을 멈추고 자가 채점으로 돌린다. 실측 비용을 보고 모델을 정한다 (결정 필요).
- 채점 결과 JSON은 structured outputs(`output_config.format`)로 받는다. 도구 호출을 강제하는 방식(`tool_choice`)은 Sonnet 5.5와 Opus 5.5에서 400 에러가 난다.
- 그 밖의 안전장치: Console 지출 한도, 채점 기준 프롬프트 캐싱. 과거 대화 일괄 가져오기는 Batch API(50% 할인)로 한다.
- 채점 화면에 "AI 판정이며 틀릴 수 있어요" 안내를 넣는다 (Commercial Terms 요구 사항).

정해진 것:

- 서비스 이름: **모아이** (지식을 "모아" + AI, 🗿). 코드 식별자는 `moai`. 후보 50개는 [names.md](names.md)
- 런타임: TypeScript, Cloudflare Worker 하나 ([ADR 0001](adr/0001-runtime.md)). 포트폴리오 용도가 아니라서 단순함·속도·비용을 우선했다.
- 친구 요금제: Pro($20) / Max($100). 둘 다 커스텀 커넥터를 쓸 수 있다.
- 서버 LLM 호출은 내 Console API 키로 한다. 가입은 초대받은 사람만 한다.
- 배포: Cloudflare(무료 플랜, 도메인 보유). AWS와 Vercel은 쓰지 않는다.
